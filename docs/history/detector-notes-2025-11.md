# 🎶 Record Scan — Dataset & Annotation Pipeline

This repo powers the Record Scan dataset workflow — mobile/web annotation → YOLOv8 dataset export → model training to detect album covers in real photos.

---

## Repository Structure

.

- album-annotator/ Next.js web app to upload photos and draw bounding boxes
- album_dataset/ YOLO-format dataset (images + labels) generated by export
- album_cover.yaml YOLO dataset configuration
- export_yolo_dataset.py Supabase → YOLO dataset exporter
- README.md

---

## album-annotator (Next.js + Supabase)

A minimal web app (desktop or phone) to:

- take/upload a photo (uses the phone camera on mobile)
- draw one axis-aligned bounding box around the album cover
- save normalized YOLO coordinates to Supabase
- store the photo in Supabase Storage

Endpoints:

- /api/upload → uploads image to Supabase Storage and returns a public URL
- /api/save → inserts one row into the `annotations` table
- /annotate → main annotation UI (also used as home route via redirect)

Environment variables (set in Vercel and in .env.local for local dev):

- NEXT_PUBLIC_SUPABASE_URL=<your_supabase_url>
- NEXT_PUBLIC_SUPABASE_ANON_KEY=<your_supabase_anon_key>

Row-Level Security (RLS):

- Storage bucket (album-images): allow public INSERT/SELECT (or disable RLS during prototyping)
- Table `annotations`: add policies to allow anonymous INSERT and SELECT (Check/Using: true)

## album_dataset (YOLO folder layout)

Created by export_yolo_dataset.py:

album_dataset/

- images/
  - train/
  - val/
- labels/
  - train/
  - val/

Each label file (labels/\*_/_.txt) uses YOLO format:

- class_id x_center y_center width height
- all values normalized to [0, 1]
- class_id = 0 for album_cover

## album_cover.yaml (YOLO dataset config)

Example:

path: album_dataset
train: images/train
val: images/val
nc: 1
names: ["album_cover"]

Train with YOLOv8:

yolo detect train data=album_cover.yaml model=yolov8n.pt epochs=100 imgsz=640

## export_yolo_dataset.py (Supabase → YOLO)

What it does:

1. Connects to Supabase (annotations table + Storage public URLs)
2. Fetches all annotations
3. Randomly splits 85% train / 15% val
4. Downloads images to album_dataset/images/{train|val}
5. Writes YOLO labels to album_dataset/labels/{train|val}

Dependencies:

pip install supabase requests tqdm python-dotenv

Environment loading (recommended):

- reuse album-annotator/.env.local
- add near the top of the script:
  from dotenv import load_dotenv
  load_dotenv(dotenv_path="album-annotator/.env.local")

and then read:

- SUPABASE_URL = os.getenv("NEXT_PUBLIC_SUPABASE_URL")
- SUPABASE_KEY = os.getenv("NEXT_PUBLIC_SUPABASE_ANON_KEY")

Run export:

python3 export_yolo_dataset.py

After it finishes, album_dataset/ is ready for YOLO training.

## Workflow Summary

1. Open the annotator (phone or desktop), take/upload photos, draw a box, save.
2. Run export_yolo_dataset.py to build album_dataset/ with train/val splits.
3. Train YOLOv8 using album_cover.yaml.
4. Use the trained detector in your retrieval pipeline to isolate and rectify covers before embedding.

---

## Notes & Best Practices

- Annotate only one class: album_cover (front face of the sleeve).
- Keep boxes axis-aligned; rotation/perspective is handled later in preprocessing.
- Aim for diverse training photos: angles, glare, lighting, distance, partial cuts.
- Start small (100–300 images), train, review errors, add more hard cases, retrain.
